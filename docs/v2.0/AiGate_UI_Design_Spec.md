## 一、设计目标与定位

### 1.1 产品定位（来自 PRD §1.2）
AiGate 是面向中大型企业的**企业级 AI 全栈管控平台**。UI 必须传达：

- **统一管控**：网关代理所有模型调用
- **多租户治理**：集团 → 分公司 → 部门 → 员工 四级结构
- **资产化**：MCP 工具与知识库作为企业资产，可注册、授权、计费、审计
- **智能化**：AiGate Bot（管理 Agent）+ 项目 Agent 双层智能体系
- **合规可审计**：调用日志 180 天 + 操作审计 365 天

> **一句话**：让企业 AI 调用 **可管、可控、可追溯**。UI 的每一屏都要回答"谁在用、用了多少、用得是否合规"。

### 1.2 设计原则

1. **信息密度优先**：管理控制台是高密度信息系统，不做"大留白 SaaS 落地页"。每一屏的核心 KPI、风险、操作入口必须 above the fold。
2. **角色驱动**：同一页面对不同角色（集团 IT / 分公司管理员 / 部门负责人 / 项目负责人 / 员工）展示不同信息切片。
3. **可解释**：任何数据卡片旁都应有"它从哪儿来、怎么算的"提示；任何拦截/降级行为都应有原因。
4. **闭环表达**：网关 → 配额 → 资产 → Agent → 审计 → 预警，UI 上要能从任意环节一跳到上下游。
5. **反 AI Slop**（来自项目规则）：禁紫蓝渐变、禁 Emoji、统一 SVG 图标、毛玻璃顶栏。
6. **渐进披露**：列表 → 抽屉详情 → 详情页，避免在列表里堆所有字段。

### 1.3 三大设计风格（已就位，必须保持）

`UI/style.css` 已通过 CSS 变量实现三主题切换，新增页面**必须**沿用：

| 风格 | 类名 | 主色 | 强调色 | 圆角 | 阴影 | 适用场景 |
|---|---|---|---|---|---|---|
| 暗黑科技（默认）| `dark` | Emerald `#10b981` | Amber `#f59e0b` | 0.75rem | 无 | 管理后台默认 |
| 杂志白亮 | `light` | Orange `#ea580c` | Emerald `#059669` | 0 | `4px 4px 0 #111` | 印刷感、合规审计 |
| Apple 拟物 | `apple` | `#0066cc` | `#ff3b30` | 1.125rem | 毛玻璃 | 高端客户演示 |

> 任何新增页面都不得引入"主题外色彩"。新主色必须先在三主题下都验证。

## 二、视觉设计系统

### 2.1 设计 Token

| Token | dark | light | apple |
|---|---|---|---|
| `--bg-body` | `#09090b` | `#ffffff` | `#f5f5f7` |
| `--bg-surface` | `#18181b` | `#ffffff` | `rgba(255,255,255,.65)` |
| `--border-color` | `#27272a` | `#111827` | `rgba(0,0,0,.05)` |
| `--text-primary` | `#f4f4f5` | `#111827` | `#1d1d1f` |
| `--text-secondary` | `#a1a1aa` | `#6b7280` | `#86868b` |
| `--brand-main` | `#10b981` | `#ea580c` | `#0066cc` |
| `--brand-accent` | `#f59e0b` | `#059669` | `#ff3b30` |

### 2.2 字体

- **Display / Body**：`ui-sans-serif, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- **Mono（数据 / Token / API Key）**：`ui-monospace, "JetBrains Mono", Consolas, monospace`
- **字号阶梯**：`12 / 14（默认）/ 16 / 18 / 20 / 24 / 30 / 36`
- **行高**：正文 `1.6`，标题 `1.25`，数据指标 `1.0`

### 2.3 间距与栅格

- **基础单位**：4px。常用 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`
- **页面容器**：`max-w-7xl mx-auto`（约 1280px）
- **卡片内边距**：`p-6`（默认）/ `p-4`（次级）/ `p-8`（hero）
- **卡片间距**：`gap-6`（默认）/ `gap-4`（密集列表）

### 2.4 图标规范

- **库**：Lucide（已在用）。**禁止** Emoji 与 Heroicons solid 混用。
- **尺寸**：12 / 14 / 16（行内）、18（导航/列表）、20 / 24（按钮/标题伴随）、36 / 48（空状态）。
- **`stroke-width`**：默认 2，需要强调时 2.5。

### 2.5 状态色

| 语义 | 色 | 用途 |
|---|---|---|
| 正常 / 成功 | `--brand-main` | 网关健康、配额充足、向量化完成 |
| 警告 | `--brand-accent` | 配额 70%/90%、密钥即将过期、MCP 健康降级 |
| 错误 / 拦截 | `--brand-accent` 加深背景 | 配额耗尽、密钥已封禁、MCP 不可用 |
| 中性 | `--text-secondary` | 草稿、未启用、历史 |

### 2.6 Badge / Tag 规范

- **状态徽章**：`badge-success` / `badge-warning` / `badge-neutral`（待新增）
- **数量徽章**：圆点 + 数字（顶栏铃铛、侧边栏待办计数）
- **角色徽章**：`SYS` / `TENANT` / `PROJ` / `USER`，统一深底白字
- **环境徽章**：`PROD` / `STAGING` / `DEV`，与密钥前缀 `ag-prod-/ag-stg-/ag-dev-` 对齐

## 三、信息架构与全局导航

### 3.1 顶部导航（master-nav，必须毛玻璃）

从左到右：

1. **Logo + 产品名 + Edition 标签**（`Enterprise` / `Pro` / `Community`）
2. **租户切换器**（仅集团 IT 管理员显示）— 可切换「集团 / 北京研发中心 / 上海...」视角
3. **全局搜索**（`⌘K` / `Ctrl+K` 唤起）— 同时检索：员工、密钥、MCP 工具、知识库文档、Agent、近期日志、操作审计
4. **AiGate Bot 入口**（自然语言查运营数据，固定在顶栏，弹出对话面板）
5. **预警铃铛**（带未读数 + 下拉预览，已就位）
6. **用户头像下拉**（详见 §3.1.1）

> **说明**：原顶栏中的「主题切换 segmented control」与「模拟身份 select」从顶栏移除——主题切换收纳到头像下拉；角色模拟仅在演示模式下从头像下拉触发，避免污染生产 UI。

#### 3.1.1 头像下拉菜单（取代左侧「个人中心」入口）

个人相关功能**全部归口**到右上角头像下拉，不再占用左侧主导航位置。

**交互**：
- 头像点击即展开（不需要 hover），按 `Esc` 收起
- 「个人资料 / 我的密钥 / 我的用量 / 通知偏好 / 安全设置」均使用**右侧 Drawer**展示，不离开当前业务页面
- 「切换租户」二级菜单为搜索式 popover（租户多时支持过滤）
- 「主题 / 语言」内联切换，立即生效并写 localStorage
- 「退出登录」需 modal 二次确认；执行 `POST /auth/logout` + 清除 token + 重定向 `login.html`

> **v1.4 关键变更**（来自评审反馈）：
> 1. **知识库独立**：知识库是强隔离的**项目专属隐私数据**，从"资产市场"移出单独成组，消除任何"可能被共享"的合规暗示。
> 2. **Agent 中心独立**：Agent 是顶层智能体，消费"知识库数据" + "AI 资产能力"，提升为独立一级。
> 3. 确立了「纵向项目数据 (知识库) + 横向通用能力 (资产市场) = 顶层智能体 (Agent)」的架构逻辑。

### 3.3 全局基础设施（每页都需要）

这一组组件不属于任何模块，但**每个页面都依赖**，必须在 v1.1 阶段先沉淀：

#### 3.3.1 PageHeader（页眉）

```
┌─────────────────────────────────────────────────┐
│ [面包屑] 组织治理 / 组织与配额 / 北京研发中心    │
│                                                  │
│ 北京研发中心          [租户级]   [主操作 ▾]   │
│ 本月已用 ¥15,000 / ¥50,000   [次操作]            │
│ 数据时效：30 秒前更新 [刷新]                       │
└─────────────────────────────────────────────────┘
```

包含：面包屑 / 标题 / 副标题或 KPI 行 / 状态徽章 / 主-次操作组 / 数据时效标识。

#### 3.3.2 全局搜索（⌘K）

- 顶栏中部入口或快捷键唤起
- 分组结果：员工 / 组织 / 密钥 / MCP / 知识库文档 / Agent / 调用日志 / 操作审计
- 每条带类型徽章 + 高亮命中关键字
- `↑↓` 选择，`Enter` 跳转，`⌘ + Enter` 在新标签打开
- 检索范围按当前角色权限自动收敛

#### 3.3.3 面包屑（Breadcrumb）

所有进入「详情页」「子页面」的路径必须有面包屑。点击各级可回跳。Tab 切换时同步反映在最后一级（写入 URL `?tab=xxx`）。

#### 3.3.4 数据时效与刷新策略

| 页面 | 时效要求 | 自动刷新 | 手动刷新 |
|---|---|---|---|
| 数据大盘 | 30 秒 | ✅ 30s | ✅ 顶部按钮 |
| 调用日志 | 实时（流式追加）| ✅ SSE | ✅ |
| 预警中心 | 实时 | ✅ WebSocket | ✅ |
| 知识库文档状态 | 5 秒 | ✅ 5s（处理中时）| ✅ |
| MCP 健康监控 | 1 分钟 | ✅ 60s | ✅ |
| 其他列表页 | 进入时拉一次 | ❌ | ✅ |

所有自动刷新必须显示「最后更新 X 秒前」，避免用户误以为数据是实时但实际过期。

#### 3.3.5 筛选与 URL 同步

- 列表页所有筛选条件、分页、Tab、排序都写入 URL query string
- 用户最近一次的筛选偏好写 localStorage（key 形如 `aigate_filter_logs`），下次进入页面默认还原
- 顶栏提供「重置筛选」一键清除

#### 3.3.6 批量操作工具条

表格行勾选后，**底部浮出**操作工具条（不阻挡上方表格）：

```
┌─────────────────────────────────────────────┐
│  已选中 12 项    [限速] [封禁] [吊销] [×取消] │
└─────────────────────────────────────────────┘
```

#### 3.3.7 未保存离开提示

所有表单页（注册 MCP / 创建 Agent / 系统设置 / 知识库权限等）在有未保存变更时离开必须 modal 拦截。

| **SSO 集成** | 企微 / 钉钉 / LDAP / OIDC 配置；组织架构同步策略；账号映射规则 | PRD §1.4 / §7.1 |
| **安全策略** | 密码强度、2FA 强制范围、IP 段白名单、会话时长、密钥脱敏粒度 | PRD §5 安全 |
| **审计保留** | 调用日志保留期（默认 180 天）、操作日志保留期（默认 365 天）、导出策略 | PRD §5 合规 |
| **RAG 默认策略** | 新建知识库时的默认分块大小、重叠 Token、嵌入模型、Rerank 模型、Top-K | PRD §3.2.5 |
| **资产市场默认** | MCP / Skills / Plugins / Hooks 的默认可见性（全员 / 需授权）、公共市场是否启用、资产审核策略 | §3.6 |
| **开放 API** | Webhook 订阅、开放 API Key 管理、速率限制 | PRD §7.1 旗舰版 |

**重要规则**：
- 设置变更需立即生效，但**敏感变更**（SSO、安全策略、审计保留）需二次确认 + 操作审计落库
- 「分公司管理员」可见的 Tab 受限：基础信息（本公司）、配额规则（本公司默认）、预警规则（本公司）；无法触达 SSO / 安全策略 / 审计保留 / 开放 API
- 各 Tab 顶部显示「上次修改：张三 · 2026-04-29 14:32」，点击跳转操作审计该条记录

### 3.6 资产市场统一模式（AI Asset Marketplace）

> **设计哲学**：参考 [aitmpl.com](https://www.aitmpl.com/)。**企业内所有可复用的 AI 能力都是资产**——可注册、可授权、可计费、可版本管理、可审计。不论是 MCP、Skills、Plugins还是 Hooks，都遵循 **同一套市场模式**。

#### 3.6.1 五类资产定义与边界

| 资产类型 | 本质 | 举例 | 调用方 | 作用阶段 |
|---|---|---|---|---|
| **提示词 Prompts** | 可变量化的纯文本模板 | 「商务邮件改写」「产品描述生成」「FAQ 提炼」 | 人 / Agent | 推理前填槽 |
| **MCP 工具** | 可被 AI 调用的外部服务 | GitHub API、飞书文档、内部 ERP 查询 | Agent | 推理中 |
| **Skills 技能** | Prompt + 工作流 + 工具组合的**能力包** | 「代码审查」「需求拆解」「Bug 定位」 | Agent / 人 | 推理前组装 |
| **Plugins 插件** | 以项目/架构额外能力包扣在企业 AI 上的能力 | 「Claude Memory 插件」「镜像生成插件」 | 平台 / Agent | 多阶段 |
| **Hooks 钩子** | 在调用生命周期点插入的代码 | 「调用前敏感词过滤」「调用后自动埋点」「超资拦截限速」 | 网关 自动 | before/after/error/abort |

**提示词 vs Skill 边界（常被混淆）**：
- **Prompt = 原子级文本模板**，只含变量插槽。例：
  ```
  请用专业的语气审查以下 {{language}} 代码，重点关注 {{focus_area}}：
  {{code}}
  ```
- **Skill = Prompt + 多步流程 + 工具调用**。例：「代码审查」Skill = 调 git diff 拿修改 → 调 lint 拿问题 → 用 Prompt 总结 → 输出 Markdown 报告
- **一句话**：Skill **包含**一个或多个 Prompt；Prompt 可被多个 Skill / Agent 复用。两者都属于资产市场，但颗粒度不同。

> **与知识库的区别**：知识库是**项目专属数据资产**，隐私性强，绝不进入任何公共市场；MCP / Skills / Plugins / Hooks / Prompts 则是**可跨项目复用的能力资产**。
> **与 Agent 的关系**：Agent 消费以上资产（本项目知识库 + 授权市场资产），对外提供封装好的服务，Agent 本身独立于上述所有，作为顶层应用。

#### 3.6.2 统一信息架构（四类资产页面结构一致）

```
顶部 Tab：[ 公共市场 ] [ 企业私有库 ] [ 调用统计 ]
         ───────────────

[公共市场]                          [企业私有库]
  · 分类筛选                            · [+ 注册 / 上架 资产]
  · 精选资产卡片                          · 已发布 / 草稿 / 已下线 Tab
  · 官方认证标                          · 资产卡片加：版本 / 健康灯 / 权限
  · 已开通状态                          · 从公共市场开通的会同步出现在这里
  · 调用成本估算
  · [查看详情] [一键开通]
```

#### 3.6.3 资产详情页统一模板

任一资产（mcp / skill / plugin / hook）的详情页都是同一套 Tab架构：

| Tab | 内容 |
|---|---|
| **概览** | 资产名 / 提供方 / 分类 / 描述 / 当前版本 / 健康状态灯 / 官方认证徽章 / 理论调用成本 |
| **使用说明** | 如何在 Agent 中调用 / 使用示例 / 入参出参 / Markdown 渲染 |
| **健康监控** | 近 24h / 7d 调用成功率折线 + 失败事件时间线 |
| **调用统计** | 日/周/月调用量 + Top 调用方 + Token 消耗 + 估算费用 |
| **权限授权** | 行=项目/部门/成员，列=可调用；批量勾选 |
| **版本管理** | 版本列表 + 变更说明 + 发布 / 回滚（需权限） |
| **审计日志** | 资产本身的变更记录（注册/授权/发布/回滚/下线） |

#### 3.6.4 资产创建 / 注册向导（统一体验）

四类资产都使用「顶部右侧「+ 注册」按钮 → 抽屉向导」的同一路径：

```
[1] 基础信息      名称 / 分类 / 图标 / 描述 / 供应方
[2] 资产主体      （随资产类型分化，见下表）
[3] 成本 / 计费   Token 估算 / 调用限额 / 默认可见性
[4] 权限授权      项目 / 部门 / 成员多选（可后续调整）
```

「资产主体」步骤差异：

| 资产 | 主体定义 |
|---|---|
| Prompt | 提示词文本（Markdown）+ 变量插槽声明（名称/类型/默认值/必填）+ 适用模型范围 + 示例输入 + 期望输出 |
| MCP | 服务 URL / 协议（stdio/SSE/HTTP）/ 认证 / 健康检测点 + 联通性测试 |
| Skill | YAML/JSON 描述文件上传（system prompt + 依赖工具清单 + 调用样例）或可视化构造器 |
| Plugin | 代码包上传（zip）或 Git URL + 生命周期钩子声明 + 静态扫描报告 |
| Hook | 触发点选择（before/after/error/abort）+ 代码主体（泙样区 + 其他语言透过 sandbox）+ 超时与降级策略 + 安全审查状态 |

#### 3.6.5 公共市场与私有库的主要差别

| 项 | 公共市场 | 企业私有库 |
|---|---|---|
| 提供方 | AiGate 官方 · 社区贡献 | 企业自建 |
| 上架审查 | 平台审核 | IT 管理员需审查（Hooks 必须）|
| 可见性 | 全环境可见 | 仅本企业 |
| 开通动作 | 一键开通 → 进入本企业库 | 注册/上传 → 审查 → 上架 |
| 计费 | 部分付费资产另计费 | 仅 Token 调用成本 |
| 版本 | 跟随上游 | 企业自控 |

#### 3.6.6 资产与 Agent / 网关的集成点

- **Agent 创建向导**：绑定阶段从「只选知识库 + MCP」扩展为「**知识库 + Prompts + MCP + Skills + Plugins**」五类选项；Hooks 不在这里绑定（它们是网关级作用域）
- **Prompt 变量填槽**：Agent 调用 Prompt 资产时，变量来源三路：用户对话输入、从知识库 RAG 检索、从 MCP 调用结果提取
- **网关集成**：Hooks 在网关中间件链中生效（before → 鉴权 → 配额 → 权限 → 转发 → after），需提供「作用范围」配置：全局 / 某租户 / 某项目 / 某 Agent
- **调用计费**：资产产生的 Token 消耗都计入**调用方配额**（PRD §3.2.4 对 MCP 所述，本原则扩展到五类资产）

- 长度统计：字符数 / 估算 Token 数（按选定模型）

#### 5.18.4 版本与 A/B

- 每次保存自动建快照，可命名为正式版本（如 `v1.2.0`）
- 同时可设 **A/B 流量**：默认 v1.2.0 占 80%、v1.3.0-beta 占 20%
- 流量分配在网关侧落地，调用日志自动带 `prompt_version` 维度

#### 5.18.5 与 Agent / 员工调用的绑定

- **Agent 创建向导**：第 2 步「绑定知识库 + Prompts」中可勾选多个 Prompt，作为 Agent 的"能力库"
- **员工直接调用**：在「我的工作台」一键插入 Prompt 到对话；变量自动表单化
- **API 调用**：员工通过 ag-key 在客户端用 `prompt_id` + 变量字典调用，网关组装后转发

#### 5.18.6 「我的草稿」与上架审核

- 所有员工都能在「我的草稿」自由创建 Prompt，仅自己可见
- 申请上架 → 项目负责人 / 部门负责人 / IT 管理员逐级审核（按 Prompt 涉及的可见范围）
- 审核维度：内容合规 / 命名规范 / 变量声明完整 / 沙箱测试通过率 / 不含敏感词

## 九、文案与图标规范

### 9.1 文案语调

- **直接、专业、精确**。例：「配额已耗尽」而非「哎呀，配额好像不够了～」
- **数据精确**：金额保留两位小数 + ¥；Token 用 `K/M/B` 缩写时悬浮显示精确值
- **时间**：相对时间（"10 分钟前"）+ 悬浮绝对时间
- **不出现 Emoji**（项目硬规则）
- **中文标点**：用「」不用 ""，用——不用 ---

### 9.2 状态术语统一

| 含义 | 用语 |
|---|---|
| 启用 / 停用 | 已启用 / 已停用（不用「开/关」「在/不在」）|
| 通过 / 拒绝 | 已通过 / 已驳回（不用「同意/不同意」）|
| 删除 | 删除 / 吊销（密钥）/ 下线（MCP/Agent）|
| 配额 | 配额（不用「额度」「限额」混用）|
| 调用 | 调用（不用「请求」混用，除非指 HTTP request）|

### 9.3 图标

- 统一 Lucide。常用映射：
  - 数据大盘：`bar-chart-3`
  - 组织：`users-2` / `building-2`
  - 密钥：`key`
  - 日志：`file-text`
  - MCP：`puzzle` / `unplug`
  - 知识库：`book-open`
  - Agent：`bot`
  - 预警：`bell`
  - 审计：`shield-check`
  - 套餐：`receipt`

### 14.8 摘要：必须立即决策的 5 件事（🔴 红线）
