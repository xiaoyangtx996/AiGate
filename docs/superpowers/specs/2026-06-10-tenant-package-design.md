# 阶段 5：租户套餐与生命周期 设计 spec

> 日期：2026-06-10
> 总纲：`2026-06-10-aigate-v2-roadmap-overview.md`
> 参考：ruoyi-ai（sys_tenant / sys_tenant_package：套餐=菜单集合、过期时间、账号配额、动态切换）
> 前置依赖：阶段 0+1 完成（显式租户上下文、菜单幂等种子）；可与阶段 3/4 并行

---

## 范围

**范围内**：租户套餐（菜单集合）、租户（顶级组织）生命周期字段（过期/账号配额/停用）、菜单按套餐裁剪、配额与过期的运行时拦截、管理页面。
**范围外**：付费计费/续费支付流（ruoyi 企业版范畴）、租户独立数据库/Schema 隔离（沿用行级 organizationId 隔离）、租户自助开通注册。

## 概念约定

**租户 = organization 表中 `type` 为顶级（group/company）的节点**。套餐、过期、账号配额只挂在顶级节点上，其下部门/团队继承生效。不另建 tenant 表，避免与现有四级组织模型撕裂。

## 数据模型

### tenant_package 表（新增）

| 字段                      | 说明                                                                          |
| ------------------------- | ----------------------------------------------------------------------------- |
| `id / name / description` | 套餐名（如「基础版」「专业版」）                                              |
| `menuCodes`(json)         | 菜单 code 数组（**用 code 不用 id**，与幂等种子的 code 对齐，环境间迁移稳定） |
| `enabled / sort`          |                                                                               |

### organization 表（扩展，仅顶级节点使用）

| 新增字段       | 说明                                             |
| -------------- | ------------------------------------------------ |
| `packageId`    | nullable；空 = 不受套餐限制（兼容现状）          |
| `expireTime`   | nullable；空 = 永不过期                          |
| `accountLimit` | int, default -1；-1 = 不限（ruoyi 约定）         |
| `tenantStatus` | `active / suspended`；suspended = 管理员手动停用 |

## 运行时规则

### 菜单裁剪（动态交集，不做 ruoyi 的 syncTenantPackage 拷贝）

`menu-manage/index.get.ts` 在现有角色过滤之上叠加：非 admin 用户，取其 activeOrganization 的**顶级祖先**节点 → 有 packageId 则菜单 = 角色菜单 ∩ 套餐 menuCodes。动态交集意味着改套餐立即对全租户生效，无需同步任务（相对 ruoyi 的简化决策）。

### 账号配额

成员加入（member 创建）时统计该顶级组织子树内去重用户数，达到 accountLimit 则拒绝并提示「账号数已达套餐上限」。

### 过期与停用拦截

`server/middleware/auth.ts` 在 principal 解析后增加检查：activeOrganization 顶级祖先 `expireTime` 已过或 `tenantStatus = suspended` 时——

- 非 admin 用户：除登出与切换组织端点外，业务 API 返回 403 + 明确文案（「租户已过期，请联系管理员」/「租户已停用」）。
- admin：不拦截（需要进去处理）。
- 前端：全局错误处理识别该 code，跳转专用提示页（含原因与联系方式），不再弹散落 toast。

到期前预警：复用现有 alert 机制，新增规则类型「租户到期 14/7/1 天」，每日定时任务扫描生成告警。

## API 与页面

| 项                                           | 说明                                                                                                 |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `tenant-package` CRUD（admin only）          | 标准 CRUD                                                                                            |
| 套餐管理页 `system-settings/tenant-packages` | 列表 + 编辑 Drawer：名称/描述 + **菜单树勾选**（复用角色管理页的菜单树组件）                         |
| 组织管理增强                                 | 阶段 0+1 的组织弹窗中，顶级节点额外渲染：套餐下拉 / 过期时间 / 账号配额 / 启停开关；非顶级节点不显示 |
| 组织列表/树                                  | 顶级节点显示套餐徽章 + 到期倒计时（≤14 天黄、≤7 天红）+ 停用置灰                                     |
| 租户视角                                     | admin 经阶段 1 的组织切换器选中某租户后，所见菜单/数据即该租户实况（巡查能力，无需新功能）           |

菜单：「系统设置」组新增「租户套餐」（admin only，幂等种子补充）。

## 验收标准

1. 建套餐「基础版」（仅勾选工作台 + AI 资产组菜单）→ 绑定到某公司 → 该公司普通用户登录只见交集菜单；admin 不受影响。
2. 修改套餐菜单集合 → 该租户用户刷新后菜单立即变化（无同步任务）。
3. accountLimit=3 的租户加入第 4 个成员被拒绝，提示明确。
4. 将租户 expireTime 改为昨天 → 其普通用户任意业务请求 403 并落到过期提示页；admin 仍可操作并续期后恢复。
5. 到期前 7 天出现告警记录。

## 风险

| 风险                     | 缓解                                                                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 顶级祖先查询每请求一次   | principal 解析处对「orgId → 顶级祖先 + 套餐/过期」做进程内 60s 缓存（管理变更容忍 1 分钟生效延迟；停用走立即失效：变更端点主动清缓存） |
| 套餐误删导致租户菜单全空 | 删除套餐前校验无组织引用；被引用时禁止删除                                                                                             |
| packageId 为空的存量租户 | 规则定义为「空 = 不限制」，平滑过渡                                                                                                    |
