## 范围

**范围内**：五个工作包——系统设置聚合页、全局搜索 ⌘K、个人功能补全、用户管理增强、预警规则对齐。WP 间互不依赖。
**范围外**：SSO 集成 Tab、白标定制、开放 API Tab（均挂起）；移动端适配。

## WP1 系统设置聚合页

**现状**：无聚合配置页；各处配置散落或硬编码（如审计保留期、密钥默认有效期）。其他阶段 spec 已引用「系统设置」概念（阶段 4 RAG 默认策略、阶段 6 调试模式），本 WP 给它们一个家。

### 数据模型

**system_setting 表（新增）**：`id / scope(global | org) / organizationId(nullable) / key / value(json) / updatedBy / updatedAt`，`(scope, organizationId, key)` 唯一。读取规则：org 级有值用 org 级，否则回退 global，再回退代码内默认值。封装 `getSetting(key, orgId?)` / `setSetting(...)` 工具（进程内 60s 缓存，写入即失效）。

### 页面（新增 `system-settings/settings.vue`，左 Tab 导航 + 右表单）

首批 Tab 与配置项：

| Tab          | 配置项（key 前缀）                                           | 消费方              |
| ------------ | ------------------------------------------------------------ | ------------------- |
| 基础信息     | 平台名称、Logo、默认语言                                     | 布局/登录页         |
| 密钥默认     | 默认有效期天数、单人活跃密钥上限（默认 3）、默认每日调用上限 | api-key 创建逻辑    |
| 预警规则     | 12 类规则的阈值/启停（见 WP5）                               | alert 引擎          |
| 通知渠道     | 告警邮件收件人、resend 发件配置、Webhook URL                 | alert-notify.ts     |
| RAG 默认策略 | 新建知识库默认 chunkSize/overlap/topK/dedupStrategy          | 阶段 4 创建表单预填 |
| 审计保留     | 调用日志保留天数（默认 180）、操作日志保留天数（默认 365）   | log-cleanup 任务    |
| 高级         | 网关调试模式（请求体落库开关，阶段 6）、会话时长             | gateway / auth      |

规范：每项带说明 tooltip；敏感变更（审计保留缩短、调试模式开启）二次确认 + 落审计（阶段 6 auditLog）；Tab 顶部显示「上次修改：人 · 时间」（取该 Tab keys 的最新 updatedAt/updatedBy）。admin 可改 global 与任意 org；普通管理场景暂不开放（首版仅 admin 可见本页）。

## WP2 全局搜索（⌘K）

- **入口**：顶栏搜索框 + `Ctrl/Cmd K` 快捷键唤起 Modal。
- **后端**：`GET /api/aigate/search?q=`，并行 ILIKE 检索（每类 limit 5）：用户（name/username）、组织、API 密钥（别名）、MCP 工具、知识库、Agent、Prompt。结果按 principal 过滤（非 admin 仅本组织 + 本人资源），返回 `{ type, id, title, subtitle, route }` 分组数组。
- **前端**：分组结果 + 类型徽章 + 关键字高亮；`↑↓` 选择、`Enter` 跳转、`Esc` 关闭。防抖 300ms，q 长度 ≥ 2 才发请求。
- 不做：调用日志/审计全文检索（量大，需独立索引方案，挂起）。

## WP3 个人功能补全（头像下拉归口）

**现状**：我的密钥（my-api-keys）、我的工作台已有页面；缺通知偏好与安全设置；用户无法自助改密码。

1. **头像下拉菜单**（布局组件改造）：个人资料 / 我的密钥（跳已有页）/ 我的用量（跳工作台）/ 通知偏好 / 安全设置 / 退出登录（二次确认）。
2. **个人资料 Drawer**：头像、显示名编辑（better-auth `updateUser`）；username/组织只读。
3. **安全设置 Drawer**：修改密码（better-auth `changePassword`，需当前密码）；会话列表 + 登出其他设备（multiSession 已启用，调 `revokeSession`）。
4. **通知偏好 Drawer**：user_notification_pref 表（新增：`userId / alertType / channels(json)`）——按预警类型勾选接收渠道（邮件/站内）；alert-notify 发送前查偏好过滤。

## WP4 用户管理增强

1. **批量导入**：用户管理页 [导入 CSV] —— 模板列：username / 显示名 / 初始密码 / 角色 code / 组织路径；服务端逐行经 admin createUser + member 创建，返回逐行成功/失败报告；email 按 D5 规则派生。
2. **离职处理向导**（用户行操作 → Drawer）：勾选执行项——封禁账号（admin 插件 banUser）→ 吊销其全部 API 密钥 → 移除全部 member 关系 → （可选）其创建的 Agent/知识库转交指定用户（更新 createdBy/ownerId）。每步落审计，执行结果逐项反馈。

## WP5 预警规则对齐（12 类）

**现状**：alert / alert_rule 表与规则页已存在。**设计**：规则类型枚举对齐 UI 规范 §5.9 全集——配额 70/90/100%、套餐（租户）到期 14/7/0 天（阶段 5 已建）、密钥到期 7/1 天/已过期、异常调用 5xx 激增、MCP 不可用、知识库存储 80%、Agent 调用异常。每类：默认阈值（WP1 设置页可调）、严重级别色、推荐处置动作文案。检测任务统一进每日/每 5 分钟两档定时器（按类型归档）。告警列表增加分类 Tab 与处理状态流（未处理/已确认/已解决）。

## 验收标准

1. 设置页改「调用日志保留 90 天」→ log-cleanup 按新值执行；敏感变更出现审计记录与二次确认。
2. ⌘K 搜「张」→ 用户/Agent/Prompt 分组命中并可跳转；普通用户搜不到他组织的资源。
3. 用户自助改密码后旧会话密码失效；「登出其他设备」后另一浏览器会话失效。
4. CSV 导入 10 行（含 2 行错误数据）→ 8 成功 2 失败且原因明确；离职向导执行后该用户密钥全部吊销、登录被拒。
5. 密钥设 1 天后过期 → 出现「密钥即将过期」告警，关闭该用户邮件偏好后不发邮件仍有站内记录。

## 风险

| 风险                         | 缓解                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| 设置项消费方散落、读取不一致 | 全部经 `getSetting` 工具读取，禁止直读表；spec 列明 key 清单 |
| ILIKE 搜索性能               | 每类 limit 5 + 防抖 + 长度门槛；数据量大后再上 pg_trgm 索引  |
| 离职向导误操作               | 输入确认词（用户名）才执行；每步幂等可重跑                   |
