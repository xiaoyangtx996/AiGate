## 定位

AiGate Bot 是**平台内置的管理 Agent**：管理员与负责人用自然语言查运营数据（「上周用量最多的 3 个部门」「当前有多少异常密钥」），它将问题转化为受权限约束的统计查询并给出回答。与项目 Agent（阶段 4，用户自建）的区别：Bot 系统内置、不可删改、不绑知识库、工具集固定为平台数据查询。

## 形态（UI 规范 §14.4-16 决策落地）

- **入口**：顶栏固定图标按钮（全页面可用），点击从右侧滑出 480px Drawer 对话面板；可展开为全屏。
- **复用**：对话组件与阶段 4 的 agent-chat 共用底层（消息流、流式渲染、工具调用步骤折叠展示）。
- **快捷问题模板**：面板顶部 chips（按角色裁剪）——admin：「本月各组织 Token 消耗 Top 5」「当前异常/过期密钥」「渠道健康状况」；普通用户：「我本月的用量」「我的密钥状态」。

## 实现

### 内置工具集（受限只读查询，不暴露通用 SQL）

每个工具 = 一个白名单统计函数，**全部强制注入 principal 过滤**（admin 不限组织，其余仅 activeOrganization）：

| 工具                    | 说明                                              |
| ----------------------- | ------------------------------------------------- |
| `query_token_usage`     | 按组织/用户/模型/时间窗聚合 api_log Token 消耗    |
| `query_api_keys`        | 密钥清单与状态统计（即将过期/已禁用/异常）        |
| `query_channels_health` | 渠道与凭证健康状况（阶段 2 体检数据；admin only） |
| `query_alerts`          | 未处理告警分类计数与明细                          |
| `query_quota`           | 组织配额使用率与预计耗尽时间（线性外推）          |
| `query_agents_stats`    | Agent 对话量/异常统计                             |

工具入参经 zod 校验（时间窗 ≤ 90 天、limit ≤ 20）；工具结果以紧凑 JSON 返回给模型。

### 对话流程

1. system prompt：Bot 人设 + 当前用户角色/组织上下文 + 工具使用规范 +「数据受权限过滤」声明。
2. 模型选择：WP（系统设置，阶段 7 settings 增加 key `bot.modelId`）指定，默认取启用的第一个 chat 模型。
3. 工具调用循环复用 agent-chat；每轮工具结果在 UI 中折叠展示（工具名 + 摘要）。
4. **越权防护可视**（§14.5-26）：工具层按 principal 过滤后，若过滤导致结果集为空但全局存在数据，工具返回 `restricted: true` 标记，Bot 回复模板提示「受权限限制，部分数据不可见」。
5. 会话：复用 conversation / conversation_message 表（agent 字段指向内置 Bot 的保留 id `aigate-bot`）；历史保留最近 20 条上下文。

### API 与数据

- 不新增表；内置 Bot 不落 agent 表（保留 id 由代码常量定义，避免被 CRUD 误删）。
- `POST /api/aigate/bot/chat`（SSE 流式，鉴权后进对话循环）；`GET /api/aigate/bot/conversations` 历史会话。
- Bot 的调用消耗计入发起者所在组织配额（与项目 Agent 同规则），api_log 标记来源 `bot`。

## 页面/组件

1. 顶栏 Bot 按钮 + Drawer 面板组件（含全屏切换、清空会话、快捷模板 chips）。
2. 消息体支持 markdown 表格渲染（统计结果常以表格呈现，@nuxtjs/mdc 已有）。
3. 空状态：首次打开显示能力说明 + 模板问题。

## 验收标准

1. admin 问「本月 Token 消耗最高的 3 个组织」→ Bot 调 `query_token_usage` 并给出表格回答，工具步骤可展开查看。
2. 普通用户问同样问题 → 仅返回本组织数据，回复含「受权限限制」提示。
3. 问「有多少密钥即将过期」→ 与密钥页实际筛选结果一致。
4. 工具入参越界（如查 365 天）→ 工具拒绝，Bot 解释并改用 90 天窗口重试。
5. Bot 调用出现在 api_log（来源 bot）并计入组织配额。

## 风险

| 风险                       | 缓解                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| 模型把统计数字答错（幻觉） | 回答中数字均来自工具 JSON；prompt 要求「仅引用工具结果，不自行计算」；表格直接由工具结果渲染兜底 |
| 聚合查询被高频对话打爆     | 工具层复用阶段 6 聚合端点的 60s 缓存；单会话工具调用上限 8 次/轮                                 |
| 权限过滤遗漏               | 工具是唯一数据入口且统一走 principal 注入；vitest 对每个工具做双角色断言                         |
