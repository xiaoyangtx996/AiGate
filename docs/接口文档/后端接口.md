# AiGate 后端接口说明

> 维护位置：`docs/接口文档/`。Reqable 集合见同目录 JSON。

可导入文件：[`aigate-backend.reqable.postman_collection.json`](./aigate-backend.reqable.postman_collection.json)  
（Postman Collection v2.1 / Reqable 导入；**接口名与文档均为中文**）

## 基址

| 服务 | 地址 |
|---|---|
| 管理 API | `http://127.0.0.1:8080` |
| 网关 | `http://127.0.0.1:8081` |
| 上游阶跃 | `https://api.stepfun.com/step_plan/v1` |

## 鉴权

- 管理接口：登录后 `Authorization: Bearer <JWT>`，多数需 `platform_admin`
- 网关：`Authorization: Bearer <员工 API Key 明文>`

## 接口分组

### 01 认证与健康检查
- `GET /healthz` — 存活检查，仅表示 API 进程可响应
- `GET /readyz` — 就绪检查；数据库可连接时返回 `200 {"status":"ready"}`，否则返回 `503 {"status":"unavailable"}`

网关 `:8081` 同样提供 `/healthz`（进程存活）与 `/readyz`（数据库可连接）。
- `POST /v1/auth/login` — 登录
- `GET /v1/session` — 返回当前身份与后端权威裁剪后的 `menus`

菜单先按角色取并集，再受 `tenant_menu_settings` 裁剪：平台身份 / `platform_admin` 获得完整管理菜单；`finance_auditor` 获得用量与日志；`project_member` 获得项目、知识库与 Agent。同时具有财务和项目成员角色时返回两组菜单的并集。仅有自定义角色时不隐式授予菜单，需后续角色菜单映射能力显式配置。

### 02 用户管理
- `GET|POST /v1/users`
- `PUT|DELETE /v1/users/{id}`
- `PUT /v1/users/{id}/organization` — 调整所属部门

### 03 角色管理
- `GET|POST /v1/roles`
- `PUT|DELETE /v1/roles/{id}`

系统角色为 `platform_admin`、`project_member`、`finance_auditor`；用户可同时持有多个角色。

### 04 部门管理
- `GET /v1/organizations` — 管理员与财务审计可读，用于组织筛选
- `POST /v1/organizations` — 仅管理员创建
- `PUT|DELETE /v1/organizations/{id}`

### 05 项目成员授权
- `GET|POST /v1/projects` — 管理员列出全部项目 / 创建项目；创建时校验部门存在并自动加入创建者
- `GET /v1/project-contexts` — 管理员返回租户项目；项目成员（含财务+项目双角色）仅返回 `project_memberships` 中的项目
- `GET /v1/project-contexts?scope=usage` — 管理员/财务审计用于用量筛选时返回租户项目；避免双角色资产页越权
- `GET /v1/project-members` — 一次返回当前身份可访问项目的成员映射，减少控制台逐项目请求
- `GET /v1/project-member-candidates` — 一次返回可访问项目的候选人映射（同组织、active、尚未加入）
- `GET /v1/projects/{projectID}/members` — 项目成员列表
- `GET /v1/projects/{projectID}/member-candidates` — 仅返回项目所属组织内、active 且尚未加入该项目的员工
- `PUT|DELETE /v1/projects/{projectID}/members/{userID}`
- `GET /v1/projects/{projectID}/access`

`platform_admin` 可管理任意本租户项目成员；没有独立 `project_lead` 角色时，已有该项目 membership 的 `project_member` 作为 MVP 项目负责人，只能管理其已加入项目。

### 06 网关管理
- `GET|POST /v1/channels` — 列出 / 创建上游渠道（如阶跃）
- `PUT /v1/channels/{id}` — 更新渠道（名称、base_url、credential、active）；启用时会自动停用同租户其它渠道
- `PUT /v1/model-prices/{model}` — 设置模型单价
- `PUT /v1/quotas/{tenant|organization|user}/{id}` — 设置配额
- `GET|POST /v1/api-keys` · `DELETE /v1/api-keys/{id}`
- `GET /v1/api-logs` — 查询调用日志（可选 `user_id`、`blocked`、`from`、`to`、`limit`），响应含 `project_id/project_name`
- `GET /v1/api-logs.csv` — 原始调用日志 CSV（含项目 ID/名称），不是财务汇总

日志日期范围采用半开区间：`created_at >= from AND created_at < to`。控制台按 UTC 日传参，例如查询 2026-07-31 使用 `from=2026-07-31T00:00:00Z&to=2026-08-01T00:00:00Z`，不要使用末日 `23:59:59`。JSON 与 CSV 的项目字段均为 `project_id`、`project_name`；未归因调用返回空值。

渠道页当前维护 NewAPI sidecar 地址、加密凭证和单一 active 渠道；高级路由策略属于 post-MVP 后续能力。

### 07 审计 / 告警（Plan 03b）
- `GET /v1/audit-events` — 审计事件列表（`from`/`to`/`trace_id`/`event_type`/`limit`）
- `GET /v1/audit-events.csv` — 同上过滤条件的 CSV 导出
- `GET|PUT /v1/alert-policy` — 配额阈值与 webhook 策略（默认阈值 70/90/100；省略 `enabled` 视为 true）
- `GET /v1/alerts` — 配额告警记录列表

### 08 项目知识库 RAG（Plan 04）
- `GET /v1/projects/{projectID}/knowledge-bases` — 列出当前项目知识库
- `POST /v1/projects/{projectID}/knowledge-bases` — 创建项目知识库
- `GET /v1/projects/{projectID}/knowledge-bases/{kbID}/documents` — 列出文档与 job 状态
- `POST /v1/projects/{projectID}/knowledge-bases/{kbID}/documents?filename=` — 上传 Markdown / 纯文本 / PDF（原始文件进本地对象存储，worker 异步切片向量化）
- `GET /v1/projects/{projectID}/documents/{documentID}` — 查询处理状态（`queued|processing|ready|failed`）
- `POST /v1/projects/{projectID}/documents/{documentID}/retry` — 仅 `failed` 文档可重试
- `POST /v1/projects/{projectID}/knowledge-bases/{kbID}/search` — 检索；结果含 `citation.document_id/span_start/span_end`

环境变量：`AIGATE_OBJECT_STORAGE_PATH`、`AIGATE_OBJECT_MAX_BYTES`；可选 `AIGATE_EMBEDDING_BASE_URL` / `AIGATE_EMBEDDING_API_KEY` / `AIGATE_EMBEDDING_MODEL` / `AIGATE_EMBEDDING_DIMENSIONS`（默认本地 HashEmbedder，384 维）。**api 与 worker 必须同配置。**

### 09 网关运行时
- `POST /v1/chat/completions`（仅网关 `:8081`，OpenAI 兼容）
- `POST /v1/messages`（仅网关 `:8081`，Claude Messages 兼容；内部转成 OpenAI 再转发上游）

可选请求头 `X-AiGate-Project-ID`：经项目 ACL 校验后写入 `api_logs.project_id`，并进入对应 `audit_events.metadata.project_id`，供用量与审计直接归因。显式传入非 UUID 返回 400，`error.code=invalid_project_id`；当前 Key 用户无项目 ACL 返回 403，`error.code=project_forbidden`；未传头仍允许未归因调用。该规则同时适用于 OpenAI 与 Claude 兼容入口。

### 10 MCP 企业资产（Plan 05）
- `GET /v1/mcp/marketplace` — 读取精选公共市场；返回值不包含上游端点
- `POST /v1/mcp/marketplace/{entryID}/install` — 安装市场条目到当前租户目录，body：`{"name":"可选租户内名称"}`
- `GET /v1/mcp/assets` — 租户企业 MCP 目录；不返回原始 URL 或凭据
- `POST /v1/mcp/assets` — 注册私有 MCP，body：`{"name":"...","endpoint":"https://...","credential":"...","version":"..."}`
- `PUT /v1/projects/{projectID}/mcp/{assetID}/grants` — 授权项目或 Agent，body：`{"agent_id":""}`；空值表示项目直接调用授权
- `GET /v1/projects/{projectID}/mcp/assets` — 仅列出已对当前项目进行空 `agent_id` 授权的资产
- `POST /v1/projects/{projectID}/mcp/{assetID}/invoke?agent_id=` — AiGate 凭据中介代理，仅接受 MCP JSON-RPC `tools/call`

私有端点和凭据使用 `AIGATE_CHANNEL_ENCRYPTION_KEY` 加密落库，员工始终调用 AiGate API。调用同时写入 `mcp_usage_logs` 和 `audit_events`，上游提供时记录 input/output tokens 与 `cost_micros`，缺失时保持 NULL。注册或安装会写入 `mcp.health_check` job；`cmd/worker` 连续检查失败三次后将资产标为 `unhealthy`，写入 `mcp_health_alerts` 与审计事件。API 与 worker 必须使用同一加密密钥。

### 11 项目 Agent 与管理 Bot（Plan 06）
- `GET /v1/projects/{projectID}/agents` — 按项目列出可用 Agent
- `POST /v1/projects/{projectID}/agents` — 创建项目 Agent；可传 `knowledge_base_ids`、**已对项目授权**的 `mcp_asset_ids`、`skill_ids` 和 `skill_hook`
- `POST /v1/projects/{projectID}/agents/{agentID}/chat` — 项目成员对话，body：`{"question":"...","gateway_api_key":"员工 Key"}`。对话前会先检索绑定知识库，再对每个已绑定 MCP 调用 `tools/call`（tool=`assistant_context`）并写入 `mcp_usage_logs`；MCP 失败只写入上下文摘要，不阻断网关回答。响应含 `citations`、`gateway_trace_id`、`mcp_calls`。
- `POST /v1/bot/chat` — 仅平台/租户管理员可用的只读用量问答，body：`{"question":"今天全部项目的 LLM 与 MCP 用量和成本是多少？"}`。识别「今天/今日/today」「昨天/昨日/yesterday」「本月/这个月/this month」并按 **UTC** 半开区间过滤 `api_logs` / `mcp_usage_logs`；未写时间词则返回租户（或组织）累计全量。答句会带窗口标签（如「今日（UTC）」或「累计」）。

Agent 组装当前项目 RAG、固定版本 Skill 上下文，并对已绑定 MCP 做凭据中介调用，再请求 `AIGATE_GATEWAY_BASE_URL`（默认 `http://127.0.0.1:8081`）的 OpenAI 兼容入口；请求会附带 `X-AiGate-Project-ID`，员工 Gateway Key 只随本次请求使用，不落库。回答返回 `citations`、`gateway_trace_id` 与 `mcp_calls`，并写 `agent_messages`、`audit_events`、有界 Skill memory 与含 `skill_id` 的用量事件。绑定 MCP 或 Skill 前必须已有对应项目级显式授权。

### 12 Skill 活资产（Plan 08）
- `GET /v1/skills` / `POST /v1/skills` — 管理员列出或创建租户 Skill
- `POST /v1/skills/{skillID}/versions` — 创建不可变版本；`activate=true` 不改变既有 Agent 固定绑定
- `PUT /v1/projects/{projectID}/skills/{skillID}/grants` — 显式授权 Skill 给项目
- `GET /v1/projects/{projectID}/skills` — 项目成员列出已授权 Skill
- `GET /v1/skills/{skillID}/memories?limit=100` — 管理员读取最近调用记忆；每 Skill/Agent/用户最多 100 条
- `POST /v1/skills/{skillID}/optimize` — 优化 stub 入队，不修改 active/pinned 版本

管理 Bot 不接受 tenant/org 查询参数，只查询管理员 JWT 当前租户（或组织）范围；SQL 始终以 JWT `tenant_id` 过滤，时间窗由问题关键词解析。空问题不返回用量明细。本地市场 MCP 默认端点为 `http://127.0.0.1:18100`（`go run ./cmd/devmcp`），健康检查为 `GET {endpoint}/health`。

### 12 管理控制台用量与财务（Plan 07b）
- `GET /v1/usage/summary?from=&to=&organization_id=&project_id=` — 按 UTC 日、组织和项目返回 LLM + MCP 汇总与配额利用率
- `GET /v1/usage/cost-rollup.csv?from=&to=&organization_id=&project_id=` — 使用完全相同的过滤条件导出真正的 `day + organization + project` 财务汇总 CSV

`from` 为包含的 UTC 日起点，`to` 为排他的次日 `00:00:00Z`；省略时使用后端默认窗口。`organization_id` 与 `project_id` 都是可选过滤项：不传 `project_id` 表示当前 JWT 租户内“全部项目”（含未归因调用），不传两者表示租户汇总。控制台用量页先选组织再选项目：项目下拉会级联缩小到该组织；已选项目不属于新组织时会清空项目。用量与 CSV 仅对平台管理员、`platform_admin` / `finance_auditor` 开放，所有查询仍强制使用 JWT `tenant_id`，前端过滤条件不会扩大数据范围。

每日 JSON 行包含 `calls`、`llm_calls`、`mcp_calls`、`input_tokens`、`output_tokens`、`cost_micros`、`llm_cost_micros`、`mcp_cost_micros`、`estimated_calls`；其中 `calls = llm_calls + mcp_calls`，Token 与总成本也合并 LLM 网关 `api_logs` 和 MCP 代理 `mcp_usage_logs`。MCP 上游未提供成本时，原始日志仍保持 NULL，汇总数值按 0 计入并增加 `estimated_calls`，因此该行成本为估算下界。

成本 CSV 列顺序为：`day,organization_id,organization_name,project_id,project_name,calls,llm_calls,mcp_calls,input_tokens,output_tokens,cost_micros,llm_cost_micros,mcp_cost_micros,estimated_calls`。

项目归因优先使用 `api_logs.project_id`（网关校验通过的 `X-AiGate-Project-ID`）；仅对旧的空 `project_id` 行回退 `agent_messages.gateway_trace_id -> api_logs.trace_id`。两者皆无时显示“未归因项目”。`platform_admin` 可读写全部 07b 管理能力；`finance_auditor` 仅可只读调用日志、用量和成本汇总，不可调用项目/MCP/渠道写端点；管理 Bot 不加入财务菜单。多角色菜单按上文规则并集后再由租户开关裁剪。

## 实测注意

- 未传 `max_tokens` 时，网关按 **256** output tokens 预占配额（`DefaultOutputReserve`）；建议显式传 `max_tokens`
- Claude `/v1/messages` **必须**传 `max_tokens`
- 调用前须配置齐 **租户 + 部门 + 员工** 三级配额，否则网关返回 429 `quota_not_configured`
- Settle 时若上游 usage 大于预占，按各层级剩余额度的最小值封顶扣费，**不会**突破任一 `limit_tokens`
- 网关写 `api_logs` 同时写入 `audit_events`（同事务，`trace_id` 可串联）；配额结算后异步评估阈值并由 `cmd/worker` 投递 webhook
- 阶跃可用模型示例：`step-3.5-flash`、`step-3.7-flash`
- MVP 每租户同时仅 **一个** `active=true` 的渠道
- **不要**把厂商 API Key 提交进 git；只经「创建/更新渠道」写入
