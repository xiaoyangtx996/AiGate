# AiGate 后端接口说明

> 维护位置：`docs/接口文档/`。Reqable 集合见同目录 JSON。

可导入文件：[`aigate-backend.reqable.postman_collection.json`](./aigate-backend.reqable.postman_collection.json)  
（Postman Collection v2.1 / Reqable 导入；**接口名与文档均为中文**）

## 基址

| 服务 | 地址 |
|---|---|
| 管理 API | `http://127.0.0.1:8080` |
| 网关 | `http://127.0.0.1:8081` |
| 上游阶跃 | `https://api.stepfun.com/step_plan/v1` |

## 鉴权

- 管理接口：登录后 `Authorization: Bearer <JWT>`，多数需 `platform_admin`
- 网关：`Authorization: Bearer <员工 API Key 明文>`

## 接口分组

### 01 认证与健康检查
- `GET /healthz` — 健康检查
- `POST /v1/auth/login` — 登录

### 02 用户管理
- `GET|POST /v1/users`
- `PUT|DELETE /v1/users/{id}`
- `PUT /v1/users/{id}/organization` — 调整所属部门

### 03 角色管理
- `GET|POST /v1/roles`
- `PUT|DELETE /v1/roles/{id}`

### 04 部门管理
- `GET|POST /v1/organizations`
- `PUT|DELETE /v1/organizations/{id}`

### 05 项目成员授权
- `PUT|DELETE /v1/projects/{projectID}/members/{userID}`
- `GET /v1/projects/{projectID}/access`

### 06 网关管理
- `GET|POST /v1/channels` — 列出 / 创建上游渠道（如阶跃）
- `PUT /v1/channels/{id}` — 更新渠道（名称、base_url、credential、active）；启用时会自动停用同租户其它渠道
- `PUT /v1/model-prices/{model}` — 设置模型单价
- `PUT /v1/quotas/{tenant|organization|user}/{id}` — 设置配额
- `GET|POST /v1/api-keys` · `DELETE /v1/api-keys/{id}`
- `GET /v1/api-logs` — 查询调用日志（可选 `user_id`、`blocked`、`limit`）

### 07 审计 / 告警（Plan 03b）
- `GET /v1/audit-events` — 审计事件列表（`from`/`to`/`trace_id`/`event_type`/`limit`）
- `GET /v1/audit-events.csv` — 同上过滤条件的 CSV 导出
- `GET|PUT /v1/alert-policy` — 配额阈值与 webhook 策略（默认阈值 70/90/100；省略 `enabled` 视为 true）
- `GET /v1/alerts` — 配额告警记录列表

### 08 网关运行时
- `POST /v1/chat/completions`（仅网关 `:8081`，OpenAI 兼容）
- `POST /v1/messages`（仅网关 `:8081`，Claude Messages 兼容；内部转成 OpenAI 再转发上游）

## 实测注意

- 未传 `max_tokens` 时，网关按 **256** output tokens 预占配额（`DefaultOutputReserve`）；建议显式传 `max_tokens`
- Claude `/v1/messages` **必须**传 `max_tokens`
- 调用前须配置齐 **租户 + 部门 + 员工** 三级配额，否则网关返回 429 `quota_not_configured`
- Settle 时若上游 usage 大于预占，按各层级剩余额度的最小值封顶扣费，**不会**突破任一 `limit_tokens`
- 网关写 `api_logs` 同时写入 `audit_events`（同事务，`trace_id` 可串联）；配额结算后异步评估阈值并由 `cmd/worker` 投递 webhook
- 阶跃可用模型示例：`step-3.5-flash`、`step-3.7-flash`
- MVP 每租户同时仅 **一个** `active=true` 的渠道
- **不要**把厂商 API Key 提交进 git；只经「创建/更新渠道」写入
